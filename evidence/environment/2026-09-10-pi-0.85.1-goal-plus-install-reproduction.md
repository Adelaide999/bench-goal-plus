# Pi 0.85.1 下 Goal Plus 安装失败复现

日期：2026-09-10

状态：`reproduced`。在 77 服务器上使用 GitCode Muyuan 当时最新默认分支和
`@earendil-works/pi-coding-agent` 0.85.1，完整复现了 `pi install` 成功后
`inspect-pi.mjs` 退出 1 的问题。该结果是安装器兼容性诊断，不是 benchmark 成绩。

## 结论

根因是 Goal Plus 安装器根据 Pi CLI 入口位置错误地推导内部模块目录：

```text
Pi CLI:       .../dist/bundle/cli.js
脚本推导:     .../dist/bundle/core/settings-manager.js  (不存在)
实际模块:     .../dist/core/settings-manager.js         (存在)
```

最新版 `scripts/inspect-pi.mjs` 第 7 行使用：

```js
const core = join(dirname(realpathSync(pi)), "core");
```

Pi 0.85.1 的 executable 指向 `dist/bundle/cli.js`，所以上式得到不存在的
`dist/bundle/core`。Node 在导入 `settings-manager.js` 时抛出
`ERR_MODULE_NOT_FOUND`。这发生在读取 Pi settings、加载 Goal Plus extension 或调用模型
之前，因此与认证、provider、模型和 Goal Plus Python 依赖无关。

## 失败后的状态

安装器在校验异常后执行了预期回滚：

- 原测试目录最初没有 `settings.json`；失败后 `$PI_CODING_AGENT_DIR/settings.json` 仍不存在。
- `goal-plus-install/bindings` 和 `goal-plus-state` 下没有提交的 Pi binding。
- 已完成的 managed release 和原始日志得到保留，没有自动删除。
- 为资源解析对照而创建的独立 `pi-agent-corrected-probe` 保留了测试注册，不属于失败安装目录。
- 既有 0.84.4 runtime 和其两个活跃进程未被修改或停止。

前两次完整安装尝试因 77 的默认 PyPI 下载停滞而中止，其 incomplete release 分别保留为：

## 代码层原因

调用链如下：

```text
install.sh
  -> scripts/install.py::_install_pi
  -> pi install <managed package>                 # 成功
  -> _verify_pi_installation
  -> node scripts/inspect-pi.mjs <bundle/cli.js>  # 退出 1
  -> 恢复原 settings，撤销 pi-pending binding
  -> 顶层打印 CalledProcessError，安装器退出 1
```

`_verify_pi_installation` 通过 `capture_output=True` 运行 Node，但顶层只打印
`CalledProcessError` 的字符串，没有附带捕获的 stderr。这解释了用户日志为什么只有
“returned non-zero exit status 1”，而没有显示 `ERR_MODULE_NOT_FOUND`。

最新版 system test 也有同类固定布局假设：

```text
tests/test_installation_system.py:114
join(dirname(pi), "core/extensions/loader.js")
```

当 `pi` realpath 是 `dist/bundle/cli.js` 时，该测试同样会寻找不存在的
`dist/bundle/core/extensions/loader.js`，所以现有测试没有覆盖 bundled CLI 布局。

## 修复建议

1. 不从 CLI 的单一固定层级推导 core。至少同时检查 `dist/bundle/core` 和 `dist/core`，
   只有在目标模块都存在时才选择，并在均不存在时输出候选路径和 Pi 版本。
2. 同步修改 `tests/test_installation_system.py` 的 `PI_LOAD_CHECK`，增加
   `dist/cli.js` 与 `dist/bundle/cli.js` 两种 fixture/真实布局覆盖。
3. 在 `_verify_pi_installation` 捕获 `CalledProcessError` 时输出有界、去敏后的 stderr，
   使安装错误直接包含 Node error code 和缺失路径。
4. 修复后用同一隔离目录重新运行完整 `./install.sh --pi --yes`，要求安装器退出 0、
   extension/skill 各唯一启用一次、Pi binding 已提交且 managed runtime identity 通过。
